# Database Design

PostgreSQL 16 is the single source of truth. This document describes conventions and the logical
model per module. Column lists show the important columns; every table also has the standard columns
described in §1. The EF Core configurations in `Scholar.Infrastructure/Persistence/Configurations` are
the executable form of this document.

## 1. Conventions

| Topic | Rule |
|---|---|
| Naming | `snake_case` tables (plural) and columns; FK columns `<entity>_id`; indexes `ix_<table>_<cols>`; unique `ux_…` |
| Keys | `id uuid` primary key, UUID v7 generated by the application |
| Tenant | `school_id uuid not null` FK → `schools`, first column of composite indexes/uniques on tenant tables |
| Standard columns | `created_at timestamptz`, `created_by uuid null`, `updated_at timestamptz null`, `updated_by uuid null` on auditable tables |
| Concurrency | `xmin` system column mapped as row version on editable aggregates |
| Money | `numeric(18,2)`, never floating point; currency per school (`schools.currency_code`) |
| Instants | `timestamptz` (UTC); calendar dates `date`; clock times `time` |
| Enums | stored as `text` with check-constraint-friendly values (readable in SQL, stable across reorderings) |
| Soft delete | `deleted_at timestamptz null` only on: stored files, announcements, library titles, inventory items, learning resources |
| Text search | `pg_trgm` GIN indexes on person names, book titles |
| JSON | `jsonb` for genuinely schemaless data only: school settings blocks, audit diffs, notification payloads, template settings |

## 2. Platform & tenancy

| Table | Key columns / constraints |
|---|---|
| `schools` | `code` (unique, url-safe), `name`, `short_name`, `legal_name`, `email`, `phone`, `website`, address (`address_line1`, `address_line2`, `city`, `province`, `postal_code`, `country_code`), `timezone` (IANA, default `Asia/Karachi`), `currency_code` (default `PKR`), `locale` (default `en-PK`), `brand_color`, `logo_file_id`, `status` (Active/Suspended/Archived), `enabled_modules text[]`, `settings jsonb` (attendance, finance, academics, numbering defaults) |
| `campuses` | `school_id`, `code`, `name`, address, `phone`, `email`, `is_main`, `is_active`; `ux (school_id, code)`; partial unique: one `is_main` per school |
| `number_sequences` | the format: `school_id`, `key` (admission, application, invoice, receipt, employee, certificate, journal, purchase_order, accession, payroll…), `prefix`, `pattern` (e.g. `{prefix}-{yyyy}-{seq:5}`), `reset_policy` (Never/Yearly/Monthly); `ux (school_id, key)`. A restarting pattern must contain its period tokens (`{yyyy}`/`{yy}`, plus `{mm}` for monthly) |
| `number_sequence_counters` | one counter per period: `school_id`, `key`, `period_key` (`''`, `2026` or `202611`), `next_value bigint ≥ 1`, xmin; `ux (school_id, key, period_key)`. Advanced with a single `INSERT … ON CONFLICT DO UPDATE … RETURNING` inside the caller's transaction (row lock = serialised, rollback = gap-free). A back-dated document draws from its own period, so it can never collide with another period's numbers. Counters only move forward |
| `audit_logs` | `school_id null`, `user_id null`, `action`, `entity_type`, `entity_id`, `changes jsonb`, `ip_address`, `user_agent`, `occurred_at`; `ix (school_id, entity_type, entity_id)`, `ix (school_id, occurred_at desc)` |

**Posting rules** (see MODULES_AND_WORKFLOWS.md §Finance for the full matrix):

| Event | Debit | Credit |
|---|---|---|
| Invoice issued | Receivable (student) — net | Fee revenue per head — gross; *Concession expense debited for concession* |
| Late fee | Receivable (student) | Late fee revenue |
| Payment received | Cash register / Bank | Receivable (allocated) + Student credit (unallocated) |
| Credit applied to new invoice | Student credit | Receivable |
| Waiver / write-off | Waiver expense | Receivable |
| Payment reversed | *mirror of the original entry* | |
| Refund paid | Student credit | Cash register / Bank |
| Invoice cancelled | *mirror of the invoice entry* | |
